Archify · 扩展内版本检查与更新提示（方案 C）

name: extension_update_check · kind: workflow · 创建: 2026-10-30 · 主路径 7 + 出口 3 = 10 节点（≤12 合规）· 旁路 JSON: extension_update_check_workflow.json · 衔接：发版见 extension_release_pipeline_workflow
状态：已确认（L1-D）· 2026-10-30 定稿并落地（扩展 1.12.0）—— 只提示不代装；实现见 browser-extension/background.js 的 checkForUpdate / bumpBadge 与 popup 横幅。

批次范围

  • 动机：当前扩展以「加载已解压」安装，官方机制下永远不会自动更新（无 CRX、扩展 ID 由路径派生、update_url 被忽略）。多台设备各装一份后，没有任何渠道知道有新版本。
  • In：background.js 定时拉 latest.json 比对版本并写 storage.local；popup.html/js 顶部横幅；manifest.json 仅 bump 版本（权限不新增，host_permissions: <all_urls> 已覆盖）。
  • Out：content.js 的页面内 HUD；服务端与接管/跟踪流程（已有图）；商店上架本身；自托管 update_url（方案 B）。

设计取舍（待确认点）

  • 只提示不代装：解压加载形态下无法自更新，本批不碰 chrome.downloads 兜底逻辑，避免和接管流程抢下载。
  • 角标让位：下载进度角标优先级高于 ↑，否则用户会以为下载状态丢了。
  • 不弹系统通知：更新不是紧急事件，横幅 + 角标足够，避免打扰。
  • 版本清单托管：优先 GitHub raw 的 latest.json（零基础设施）；如果被墙导致拉不到，再改用 GitHub Pages 或仓库内静态文件。
