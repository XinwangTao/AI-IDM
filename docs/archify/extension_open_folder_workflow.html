Archify · 下载完成后打开系统文件夹

name: extension_open_folder · kind: workflow · 创建: 2026-10-22 · 主路径 6 + 出口 4 = 10 节点（≤12 合规）· 旁路 JSON: extension_open_folder_workflow.json · 前置：extension_tracking_workflow（本图接在它的 n7「终态 → 结果呈现」done 分支上）
状态：已确认（L1-D，2026-10-22 实施完成）—— 扩展 1.9.0 + 服务 1.13.0。完成通知/徽标/HUD 保持现状；越界路径一律 403。

批次范围

  • 动机：扩展把下载交给本地服务后，文件落在 download_dir，浏览器自带下载列表里看不到，用户只能手动找；希望下完就直接弹出资源管理器并选中文件。
  • 为什么必须改服务端：Chrome 扩展没有「打开任意文件夹」的 API（chrome.downloads.showDefaultFolder() 只能打开浏览器自己的下载目录，与本服务无关）。只能由本地 ai-idm serve 代开，因此新增受令牌保护的 POST /reveal。
  • In：
    • browser-extension/background.js：pollOnce() 的 done 分支调 /reveal（带 openFolder 开关 + 2s 同目录合并）
    • ai_idm/server.py：新增 POST /reveal {path}，校验路径必须落在 download_dir 内
    • browser-extension/options.html / options.js：新增「下载完成后打开文件夹」勾选项（默认开）
  • Out：content.js / engine.py / queue.py；CLI、MCP、面板触发的下载（不自动开文件夹）；完成通知与徽标时序；/status /add 等既有接口语义。

主路径（本批新增 n2–n5，n1/n6 现状保持）

是否自动打开

↓
n4 · decision（新增）
服务端校验
规范化后必须位于 download_dir 之内（防任意路径打开）；文件不存在则退回打开其所在目录
↓ 通过
n5 · step（新增）
在资源管理器中选中并置顶
Windows explorer /select,<path>；macOS open -R；其他 xdg-open <dir>。窗口出来后另起线程置顶（SetForegroundWindow → AttachThreadInput → SwitchToThisWindow，全失败则闪任务栏）；HTTP 立即返回，不阻塞队列
↓
n6 · end
原有完成收尾不变
HUD 完成卡 + 系统通知（含路径）+ 徽标 ✓ + 写回 storage（现状保持，不因打开失败而改变）

出口（全部静默，不影响下载结果）

f1 · fallback
开关关闭 / 无路径
openFolder=false 或 t.dest 为空 → 跳过 n3–n5，直接 n6

f2 · fallback
合并到上一次打开
同一目录 2s 内已有一次打开 → 跳过（防止批量下载弹出 N 个窗口）

f3 · fallback
服务拒绝或不可达
403 越界 / 404 不存在 / 超时 → 扩展静默跳过，不弹额外通知，不影响 ✓ 徽标与完成通知

f4 · fallback
系统无法打开
无图形会话、explorer 启动异常 → 服务返回 ok:false，扩展静默跳过（文件本身已下载成功）

确认结论（2026-10-22）

  • Q1 默认值：勾选项默认开，装好即生效。
  • Q2 合并策略：同一目录 2 秒内只开一次窗口。
  • Q3 触发范围：只对浏览器扩展接管的下载自动打开；CLI / MCP / 面板不打开。

  • 真实文件管理器调用：reveal_in_file_manager() 对含空格中文名的临时文件返回 (True, None)，文件不存在时返回 (False, '路径不存在')。
