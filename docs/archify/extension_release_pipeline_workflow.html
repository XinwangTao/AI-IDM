设计取舍（待确认点）

  • ZIP 而不是 CRX：两家商店都接受 ZIP 上传并由商店签名，省掉自管 .pem 的泄露风险（方案 B 才需要）。
  • latest.json 过审后才更新：先更新会让用户点到尚未上架的商店页；审核期间用 f2 的本地分发文案。
  • 版本一致性由脚本强制：manifest 与 CHANGELOG 不一致直接失败，这是这次「main 1.11.0 / 最新 Release 1.2.0」断档的直接防线。
  • 商店只上 Edge 首发：Chrome Web Store 需一次性 $5 且审核更严，等 Edge 版稳定再复用同一 ZIP 提交。
